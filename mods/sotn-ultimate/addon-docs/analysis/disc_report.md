## C. PSP ending theme (ULUS-10277)
Music: PSP_GAME/USRDIR/res/ps/{sound,snd_e}/PS_BGM/*.at3 (40 files each; 21 are byte-identical between dirs). All ATRAC3plus, 44.1 kHz stereo, 192 kb/s; ffmpeg in the VM decodes them (atrac3p), so durations are exact. Table: listings/psp_bgm_durations.txt.
Ending candidates (both byte-identical in sound/ and snd_e/):
- PS_CREDIT.at3 LBA 483232 (sound) / 415680 (snd_e), 6,701,056 B, 4:37.76 -- the credits roll song; most likely the "ending theme".
- PS_ENDDEMO.at3 1,132,416 B, 0:46.87 -- ending cutscene (demo) music; shorter.
Evidence it is the credits: file name, length (PS1 vocal ending CD track 2 is 4:11.27 US / 4:05.76 JP; PS_CREDIT is 4:37.76, so not a straight copy), no other 4+ min file named for ending. Envelope-correlation against PS1 CDDA was weak for all tracks (best PS_ENDDEMO 0.56), so I could not prove which PSP file corresponds to the PS1 vocal song; PS_CREDIT correlates only 0.22 with US CDDA. Confidence: PS_CREDIT = ending theme: medium; PS_ENDDEMO as the alternative: low-medium. Disambiguate by listening: decoded WAVs wav/psp_ref/PS_CREDIT.wav and PS_ENDDEMO.wav; PS1 CDDA WAVs wav/ps1_cdda_us_track2.wav, ps1_cdda_jp2_track2.wav (pregap stripped).
Also found: PS1 vocal ending is CD-DA track 2 (not XA) on US and JP discs; Ultimate has no CDDA track.

## D. JP narration (use image 6; XA identical in image 3 and 6)
XA_STR1 patched JP == Rev 2 byte-for-byte on audio payload (fingerprints equal). Stream inventory: listings/{jp2,us,ult}_xa_streams.txt (+ .json), per (file,chan) runs with LBA, count, coding (all 37.8 kHz stereo 4-bit in JP/US), duration. JP: music channels 0-5 (long, identical to US by sector hash), channels 6 and 7 carry 192 + 312 short voice clips each with its own file number (voice clips JP-only, 245 segments, 22.5 min, none match US).
No separate "narration" stream exists: JP and US voice clips map 1:1 (US 191/311 vs JP 192/312 segments on c6/c7, JP f69 c6 9.8 s is the same 183 sectors as US second f60). STR video/audio (OPN_WS, TYK_WS, END_WS) are identical across US/JP/Ultimate; only LOGO15XA.STR differs.
Only long JP-vs-US difference: file 30 channel 6, LBA 73,457-89,177 (JP, 1,966 sectors, 104.85 s) vs US LBA 73,356-89,156 (1,976 sectors, 105.39 s): same slot but different audio. Its envelope matches PSP sound/PS_BGM/PS_OP_NA.at3 (1:44.81 = 104.81 s) at 0.88 (JP) vs 0.77 (US); snd_e/PS_OP_NA matches US better (0.75 vs 0.68 JP). So f30 c06 is the prologue/opening piece and it is the only narration candidate (name "OP_NA" may mean opening narration; unproven). I could not verify speech vs music by ear/metrics (speech-band modulation test inconclusive). Decoded: wav/jp_f30_c06_73457.wav (104.85 s) and wav/us_ref/us_f30_c06_73356.wav for A/B; JP clips of 12 s+ in wav/jp_longclips/ (16 files, names carry LBA/file/chan). Decoder: scripts/xa2wav.c (checked: sane levels, 37.8 kHz stereo). Confidence that narration is f30 c06: low-medium; that no other dedicated narration stream exists: medium-high.
Ultimate XA is a completely new layout (55 files, 8 stereo music chans + 16 mono voice chans, 1005 segments); only 36 of 533 JP segments have matching sector hashes, so no direct stream mapping to JP/US exists.

Stage F_*.BIN graphics (61 of 67) are identical between JP, US and the patched disc, and the patch left the stage F_ files untouched; F_GAME/F_TITLE edits are the only graphics. Font location: F_GAME(.2) tail 0x2c0ae-0x31fff (plus a 14-byte change near 0x41422), plus the F_TITLE regions above. The raw format is not simple 4bpp-256 wide (I rendered ASCII to check, not legible), so font glyph dumps were NOT produced.
Text encoding (DRA.BIN of image 3): names/menus are 1 byte per char = ASCII minus 0x20 (A=0x21, a=0x41, space 0x00), e.g. offset 0x3f130 "Coral Circlet" bytes 23 4f 52 41 4c 5f 23 49 52 43 4c 45 54; terminated 0x00 here (US game terminates 0xFF). Extra codes 0x62/0x66/0x6a appear inside words ("Silver" = 33 62 56 45 52, "Helmet" = 28 6a 4d 45 54): consistent with narrow glyph variants for i/e (inference). Decoded English strings in the patched DRA (offsets): items 0x3d474-0x3f6a0 (Leather, Knife, Katana, Claymore, Mournblade, Breastplate, Goggles, Mantle, Moonstone, Megingjord...), HUD/menu 0x3f703 ("Alucard STR CON INT LCK EXP Next Gold Level Time Rooms HP MP Hearts Status Configuration ... Right hand Left hand Jump Special Wolf Mist Bat ... Sound Stereo Mono Window"), boss list 0x3f87d ("Dracula Defeated, Olrox Defeated, Legion..."), enemy names 0x4008d-0x40690. Item descriptions and dialogue are NOT plain ASCII: DRA description bytes (e.g. 0x3f140 "49 6a d4 5e 5b 9b 58...") and ST0 prologue script (ST0.BIN 0x2a20-0x2ad0, e.g. "35 56 0a 3d 5a 5c 85 5a 21 01 03 28 02 03 4f f7 84 ce 67 61...") use a custom byte code with 0x80+ values, interleaved with original JP script control codes (0x03/0x0a/0x01/0xff); original JP used Shift-JIS (82 b1 ...). I could not decode them (no table), so I cannot show dialogue samples.

## G. Area-name banners (partial)
Stage graphics files ST/*/F_*.BIN are identical in US, JP Rev2 and patched JP (61 of 67 F_ files), so banner graphics are NOT there. The patch did not alter any stage F_ file. Overlays ST/*/<stage>.BIN differ heavily between JP and US (code and data; JP overlays are about 2.2 KB smaller for most stages) and the patch changed only about 0.7-3 KB of each, i.e. hooks/code, not several-KB banners (exceptions SEL, LIB, ST0). I could not isolate the banner bitmaps or the roll vs draw effect code; no PNGs produced. Next step: diff the effect code in overlays (e.g. NZ... overlays for Alchemy Lab/Mine) or find DRA.BIN banner tables. Stage-code to area-name mapping not verified.
